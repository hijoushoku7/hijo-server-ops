# コマンド一覧

`hso` のサブコマンドと、主要なオプションの説明。手元では `hso help` でも同じ一覧が出る。
設計の背景は [cli.md](cli.md)、仕様全体は [spec.md](spec.md) にある。

```
hso <コマンド> [引数]
```

引数なしの `hso` と `hso help`（`-h` / `-help` / `--help` も同じ）はこの一覧を表示するだけで、
サーバーは起動しない。存在しないコマンドを打つと、そのコマンド名と `hso help` の案内を出して
終了コード 1 で終わる。

| コマンド | 内容 |
|---|---|
| `hso setup` | セットアップウィザードで `hso.toml` を作り、サーバー一覧へ登録する |
| `hso start [name]` | 登録済みのサーバーを起動する。名前を省くと一覧から選ぶ |
| `hso list` / `hso ls` | 登録済みのサーバーの名前・状態・設定ファイルのパスを表示する |
| `hso delete [name]` | サーバー一覧から登録を外す |
| `hso java change [name]` | サーバーが使う Java を変更する |
| `hso java list` | 自動検出した Java と、それを使っているサーバーを表示する |
| `hso version` | バージョン・表示言語・アーキテクチャを表示する |
| `hso update` | 最新リリースへ自己更新する |
| `hso uninstall` | hso 自身を削除する |
| `hso help` | コマンド一覧を表示する |

---

## `hso setup`

Minecraft サーバーのディレクトリで実行する。ウィザードが次の順で聞き、最後に
カレントディレクトリへ `hso.toml` を作ってサーバー一覧へ登録し、そのままサーバーを起動する。

1. Minecraft サーバーのディレクトリ
2. サーバー名（一覧のキーになる。初期値はディレクトリ名）
3. 起動スクリプトの選択、または直接入力
4. 作成する内容の確認

- **端末から実行する必要がある。** パイプや systemd 配下ではウィザードを出せないのでエラーになる
- 起動スクリプトに実行権限がなければ、付けるかどうかをその場で選べる
- すでに `hso.toml` がある場合は作り直さず、そのファイルを一覧へ追加するか聞く。
  登録済みなら `hso delete <name>` の案内を出して終わる
- 引数は取らない

サーバー名に使えるのは 1〜30 バイトの ASCII 英数字と `-` `_` `.` で、先頭は英数字だけ。
pidfile のファイル名になるため（→ [cli.md](cli.md) の「サーバー名の規則」）。

## `hso start [name]`

登録済みのサーバーを、いまの端末で TUI として起動する。

- 名前あり → 一覧からその `hso.toml` を引いて起動する
- 名前なし → 登録済みサーバーの一覧を出して選ばせる。端末でなければエラー
- **すでに起動中のサーバーは起動できない。** 1 サーバー = 1 hso プロセスを保つため、
  起動中のものも一覧には出るが、選ぶと「すでに起動中」と PID を添えて止まる
- 設定ファイルが見つからないサーバーは、一覧では「設定が見つからない」と表示される

## `hso list` / `hso ls`

登録済みのサーバーを表で表示する。列は名前・状態（起動中の PID / 停止 / 設定が見つからない）・
`hso.toml` のパス。引数は取らない。

## `hso delete [name]`

サーバー一覧から登録を外す。**`hso.toml` もサーバーディレクトリの中身も消さない。**

- 名前あり → そのサーバーを対象にする
- 名前なし → 一覧から選ばせる。端末でなければエラー
- 削除の前に対象の名前とパスを出して `[y/N]` で確認する。`-y` / `--yes` で省略できる
- **起動中のサーバーは削除できない。** 先に停止する

## `hso java change [name]` / `hso java list`

`hso java` を引数なしで叩くと、この 2 つの使い方を表示する。

`change` は、そのサーバーが使う Java を `/usr/lib/jvm` から自動検出した候補から選び、
`hso.toml` の `[server] java` に保存する。現在の設定には印が付く。サーバーが起動中でも
変更でき、反映は次回起動から。名前を省くと登録済みサーバーの一覧から選ぶ。端末が必要。

`list` は検出した JVM をバージョン降順で並べ、それぞれを使っている登録済みサーバーを添える。

**自動検出の対象は `/usr/lib/jvm` だけ。** SDKMAN、asdf、`/opt` などにある Java は
表示されないので、使う場合は `hso.toml` の `[server] java` に JAVA_HOME の絶対パスを書く。

## `hso version`

バージョン・表示言語（`ja` / `en`）・アーキテクチャを表示する。`hso update` が何を落として
くるかがこれで読める。新しいリリースがあれば更新を促す 1 行を添える。

`-v` / `--v` / `-version` / `--version` も同じ出力になる。`hso version` は引数を取らないが、
`-` 付きの書き方は後ろに何が付いていてもバージョンを表示する。

## `hso update`

同じアーキテクチャ・同じ表示言語のバイナリを最新リリースから取得し、SHA-256 で照合してから
自分自身を置き換える。すでに最新なら何もしない。引数は取らない。

`/usr/local/bin` に入っている場合は、**置き換えの一手だけ** `sudo` / `doas` でパスワードを
聞かれる。`sudo hso update` と打つ必要はない（取得も展開も root で走ってしまう）。

## `hso uninstall`

いま動いているバイナリ自身を削除する。削除するパスを表示して確認を取る。

| オプション | 内容 |
|---|---|
| `-y` / `--yes` | 確認を省略する。端末でないときはこれが必須 |
| `--purge` | 設定ディレクトリ（サーバー一覧）と pidfile も削除する |

- サーバーディレクトリの `hso.toml` とワールドには**触れない**
- 既定ではサーバー一覧を残す。入れ直す人のほうが多いため
- **`--purge` は root で実行しない。** root の `~/.config` を見に行き、消したい一覧が残る
- `/usr/local/bin` のバイナリを消すには `sudo hso uninstall`。uninstall 自身が
  `sudo` / `doas` を起動することはない
- 実行中のサーバーがあっても止めない。消えるのはコマンドのパスだけで、動いている
  サーバーはそのまま走り続ける

## `hso help`

コマンド一覧を表示する。引数なしの `hso`、`-h`、`-help`、`--help` も同じ。
後ろに何を付けても（`hso help start` など）コマンド一覧を表示する。

---

## オプション

| オプション | 内容 |
|---|---|
| `-config <path>` | 指定した `hso.toml` でサーバーを起動する。既定は `./hso.toml` |

`-config` はサーバー一覧を経由せずに起動する経路で、systemd unit や、サーバーディレクトリで
直に叩く使い方のために残してある。指定した設定ファイルが無く、端末から実行していれば、
その場所にセットアップウィザードで作ってから起動する。

一覧に登録されていない `hso.toml` を指定した場合は、端末なら一覧へ追加するか聞いたうえで
起動する（断っても起動はする）。
