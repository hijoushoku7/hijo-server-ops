# hijo-server-ops 仕様書

> 管理 issue: hijoushoku7/life#24

設計の決定と、**なぜそう決めたか**を残す文書。使い方は README、ビルド手順は
[build.md](build.md)。

## 概要

**hijo-server-ops**（バイナリ名 `hso`）— Minecraft サーバー用のラッパー型 TUI コンソール。
既存の起動スクリプトを hso 経由で起動すると、サーバーのログを表示しつつ、
メモリ・プレイヤー・稼働時間・ラグイベントをターミナル上のパネルに常時表示する。

**解決する課題**

- Linux サーバー上では Swing GUI（`nogui` を付けないと出るあれ）が見られない
- ヒープ使用量・プレイヤー一覧などの情報取得が個別に面倒
- `htop` は RSS しか見えず、ヒープの状況が分からない

**位置づけ**: 複数サーバーの集中管理パネル（Pterodactyl 等）ではなく、
**1 サーバーのコンソールそのものを代替する**もの。1 サーバー = 1 hso プロセス。

**ターゲット**: Linux でサーバーをホストしている人。Windows からの移行組も想定するが、
**動作対象は Linux 限定**（そもそも「Swing GUI が見られない」という課題が Windows では
成立しない）。CLI と設定ファイルで完結する前提でよく、GUI インストーラ等は不要。

## 確定仕様

| 項目 | 決定 | 理由 |
|---|---|---|
| 言語 | Go（TUI は Bubble Tea + Lipgloss） | 実行時依存ゼロのバイナリ 1 個で配れる |
| 対応 OS | **Linux 専用** | 中核の `/proc` と cgroup が Linux 依存 |
| 形態 | **ラッパー型**（サーバーを自分で起動して包む） | stdin/stdout を握れる。既存プロセスへのアタッチは対象外 |
| 対象台数 | 1 サーバー専用 | コンソールの代替であって管理パネルではない |
| 対象サーバー | v1 はバニラ / Forge / NeoForge | ログ形式が共通 |
| 起動 | 起動スクリプトのパスを設定ファイルで**明示指定** | 環境ごとに `run.sh` / `ServerStart.sh` / 手書き `start.sh` とバラバラで、自動検出は当てにならない |
| JVM 引数 | **hso は管理しない** | 責務はユーザーの `user_jvm_args.txt` / 起動スクリプトに残す。`-Xmx` の実効値は hsperfdata から読むだけ |
| フラグ注入 | `JAVA_TOOL_OPTIONS` 環境変数 | 起動スクリプトを一切書き換えない（後述） |

| TPS | v1 は対象外（ラグイベント検知のみ） | 外部から取る手段がない。v2 で Fabric mod（後述） |
| 操作 | ほぼ表示専用。矢印で選択 / Enter でフォーカス、restart / stop、コマンド送信 | |
| ログ | チャット / その他に分類して別ペイン | |

## アーキテクチャ

### プロセスの入れ子

```
hso (TUI)
 └─ 自分自身を supervisor として再実行
     └─ 起動スクリプト（setpgid・subreaper 下、JAVA_TOOL_OPTIONS 注入）
         └─ java  ← /proc の PPID を辿って PID を特定
```

supervisor を挟むのは、hso が死んだときにサーバーを孤児にしないため
（`Pdeathsig` と subreaper）。

**java の PID を特定する理由**: 掴める PID はシェルのものだが、RSS も hsperfdata も
java 本体の PID を要求する。`exec java ...` で終わるスクリプトなら PID は同一になる。
**`screen` / `tmux` を内部で使うスクリプトは stdin パイプが機能しない**ので、検出して
明示的にエラーにする（サイレントに壊れるのが最悪）。

**`JAVA_TOOL_OPTIONS` を使う理由**: 起動スクリプトの中身は任意の bash（変数展開・
条件分岐・`exec`）であり、静的パースは必ず破綻する。この環境変数は JVM が起動時に必ず
読むため、**スクリプトの中身を知らずに、ユーザーのファイルを書き換えずに** GC ログを
有効化できる。`user_jvm_args.txt` に追記するような破壊的操作を避けられる。

- 副作用: JVM が `Picked up JAVA_TOOL_OPTIONS: ...` を stderr に出すので TUI 側で除外
- `-Xmx` は注入しない。設定の記述より「JVM が実際に適用した値」（hsperfdata の
  `sun.gc.policy.maxCapacity`）の方が正確

**世代（generation）**: 起動ごとに番号を進め、UI へ送る全メッセージに載せる。
再起動前に飛んだ非同期結果（アドレス解決・メトリクス・GC・ログ）が新しい画面を
汚さないため。非同期経路を足すときは必ず generation を運ぶ。

### メトリクス取得

| 経路 | 周期 | 取れるもの |
|---|---|---|
| hsperfdata（`/tmp/hsperfdata_<user>/<pid>` を mmap 直読み） | 1s | heap used / committed / max、世代別、metaspace、GC 回数・累積時間、uptime、スレッド数 |
| `-Xlog:gc` の出力ファイルを tail | イベント | GC 後の谷、停止時間、GC 頻度 |
| `/proc/<pid>` + cgroup | 1s | RSS、CPU、memory.current / memory.max |
| 標準出力のパース | 行ごと | チャット、コマンド、参加退出、ラグ |

**`RSS - Heap committed` の差分（Δ）を明示的に出す**のが既存ツールに対する差別化点。
「`-Xmx` を積んだのに OOM Killer に殺される」の原因（Direct ByteBuffer / Metaspace /
JIT Code Cache / スレッドスタック）がそのまま可視化される。表示幅が足りないときは
分母から削り、Δ は最後まで残す。

**取れない値は推測で埋めず n/a と出す。** hsperfdata が読めない環境
（`-XX:-UsePerfData`）では RSS だけ出して heap は n/a。RSS の分母も、cgroup 制限が
あればそれ、なければ `/proc/meminfo` の MemTotal と明示する（どちらに対する割合か
読み手が取り違えるため）。CPU はコア数で割って常に 0..100% に正規化する。

ヒープはノコギリ波（GC までゴミが溜まる）なので、瞬間値だけ出すと「常に危険に見える」
UI になる。GC 後の谷を併記する。

### サーバーアドレス

起動・再起動ごとに `https://api.ipify.org` から公開 IPv4 を非同期で一度取り、
`server.properties` の `server-port` と組み合わせて Stats の先頭に出す。
`server.properties` は読み取り専用。取れなければ `Server n/a` にして理由を Log へ出す。
**取得の失敗は起動や監視を止めない。**

表示値は疎通確認済みの接続先ではない。NAT・CGNAT・プロキシ・起動引数によるポート
上書きがある環境では実際と異なりうる。

### ログ分類

バニラのログ形式を正規表現で分類する。

```
[12:34:56] [Server thread/INFO]: <player> メッセージ
[12:34:56] [Server thread/INFO]: player joined the game
[12:34:56] [Server thread/INFO]: player issued server command: /time set day
[12:34:56] [Server thread/WARN]: Can't keep up! ... skipping 50 tick(s)
```

| 分類 | 判定 |
|---|---|
| チャット | `<name> ...` 形式 |
| コマンド履歴 | `issued server command:` ＋ `[実行者: 結果]` ＋ hso 自身が送った分（自分の送信分はログに出ないので自前で記録） |
| プレイヤー増減 | `joined the game` / `left the game` / `lost connection:` |
| ラグ | `Can't keep up!` |
| その他 | 上記以外 |

**判定順が効く。** chat の後（`[Not Secure] <name> ...` を守るために必須）、
join / leave の前（`[...]` に囲まれないので衝突しない）。

バージョン差や MOD で壊れても劣化で済む形にしてある。`[実行者: 結果]` は MOD が同じ形を
出すと誤検出しうるが、プレイヤー追跡が見るのは join / leave / lag だけなので一覧は
汚れず、影響は Log ペインのノイズに閉じる。

### 画面と操作

情報密度を優先し、上段に Stats / Meters / Players、左列に Graph と Chat、右に Log、
最下段に Console を置く。主な決定と理由:

- **グラフの縦軸は 0 起点にしない。** 保持中サンプルの min / max に上下 5% の余白を
  付けた範囲へ合わせる。0 起点だと GC で数百 MB 回収されても 1 ドット未満に潰れて
  何も読めない。専用ライブラリは使わず braille 文字で描く
- **メーターは 1 本を 2 行に組む**（ラベル＋パーセント / 幅いっぱいのバー）。Meters 列は
  18〜26 桁しかなく、1 行に詰めるとバーが 10 桁前後まで削られて読めない
- **Stats のパーセントは 75% / 90% を超えたときだけ着色する。** 色が付いていること自体を
  警告として使うため。常時着色すると Meters の棒が持つ「色＝状態」と二重になり両方弱まる
- **ログは表示行数と切り離して各ペイン 500 行の履歴を持つ。** 行は端末幅に依存しない
  レコードとして保持し、切り詰めは描画時のみ。端末を縮めても履歴は消えない。スクロール
  位置は本文のバイト位置で覚える（セグメント番号だと幅を変えたとき別の場所を指す）
- **遡っている間は新着行で位置を動かさない。** ただし Esc でフォーカスを外すときは
  最新へ戻す。遡ったまま放置して新着を見落とさないため
- **プレイヤーへのコマンドは即実行せず Console 入力欄に組み立てて置く。** 実行経路を
  新設せずに済み、`ban` / `kick` の誤操作に Enter のもう一押しという確認が自然に入り、
  `tell` の本文を続けて書ける。引数の要る / 要らないで分岐させずに済むのが決め手
- **コマンド一覧はパネルの中身を差し替えずモーダルで重ねる。** 差し替えるとどの
  プレイヤーを選んだのかが見えなくなる。重ね合わせは下地の行を左右に切って挟む形で、
  切断位置が全角文字にかかったときは幅を測って空白で詰め直す（日本語のチャットや
  ログが下地になるため）
- 操作は**選択モードとフォーカスモードの 2 状態**。表示専用の Stats / Meters / Graph は
  選択対象に含めない。キー割り当ては nano 風に最下行へ常時表示する

### 設定

`hso.toml`。未知のキーはエラーにする（書き間違いを黙って無視しない）。

```toml
[server]
command = "./run.sh"      # 起動スクリプト。必須・明示指定
workdir = "/srv/minecraft"
auto_restart = true       # 異常終了したら自動で立て直す。既定は false

[ui.theme]                # 配色プリセット名
[ui.time]
offset_minutes = 90       # 表示時刻のずれ。30 分刻み・(-720, 720]
```

- **書き戻しは描画側から同期的に行う。** サーバー操作のキュー越しに頼むと、再起動中
  （最大 60 秒）に要求が詰まって落ちたり、閉じた直後に終了して書かれないまま終わる
- 一時ファイルへ書いてから rename する。途中で失敗しても元の設定を壊さない。hso が
  解釈する項目だけを書くので、ユーザーが書いたコメントは残らない
- **配色は 1 色ずつではなくプリセット**（枠 / グラフ / メーター / タイトル / 選択行 /
  ログの 6 グループ）で選ばせる。個別に変えられると、反転表示の前景と背景が同色に
  なったり、緑＝正常・赤＝危険という意味が壊れる組み合わせを作れてしまう
- **表示時刻は地域名（`time.Location`）ではなく「今が何時か」を入れさせる。** 地域名を
  選ばせるには一覧と検索が要るうえ、ユーザーが知りたいのは「手元の時計と何時間ずれて
  いるか」であって地域ではない。時は 1 時間刻み、分は 00 / 30 のみ（細かくすると秒を
  持たない入力で押すたびに端数が動く）。加算は表示側だけで行い、保存済みの `time.Time` は
  書き換えない（重ねるたびにずれが累積する）

設定ファイルが**無く**、かつ**標準入出力が端末**のときだけ対話セットアップへ入る。
パイプ越しや systemd 配下では従来どおりエラーを返す。3 ステップ（ディレクトリ入力 →
起動スクリプト候補を選択 → TOML をプレビューして確定）で、作成後はそのまま起動する。
設定を作るためだけのサブコマンドやフラグは持たない。書き込みは `O_EXCL` で既存ファイルを
上書きしない。起動スクリプトへの実行権限付与は、同意を取ったうえで行う
**hso がユーザーのファイルに触れる唯一の箇所**。

### 停止・再起動・自動再起動

終了時は java を特定済みなら Minecraft の `stop` を送って最大 60 秒待ち、終わらない
ときだけ supervisor へ SIGTERM を送る。**ワールド保存前の強制終了を通常の終了経路に
しない。** restart も同じ経路を通ってから起動スクリプトを再実行し、前世代のメトリクスと
プレイヤー状態は破棄する。

サーバーが止まっても hso は終了せず、ログを全面に出して中央にモーダルを重ね、
終了コード・稼働時間・最終メモリ・エラー行と「ログを読む / 再起動 / 終了」の三択を出す。
正常停止のときだけ 3 秒後に hso も終了する。

`auto_restart` が有効なら**異常終了のときだけ** 5 秒待って再起動する。待っている間も
背景はダッシュボードのまま残す（勝手に戻ってくる画面で操作を促さないため）。
立ち直ってもモーダルは自動で消さず、Enter を押すまで「自動再起動しました」と残す。
離席中に落ちて戻った場合、勝手に消すとクラッシュした事実が画面のどこにも残らない。

**意図された停止は自動再起動の対象にしない。** 判定は 2 経路:

1. hso のコンソールに `stop` / `/stop` が打たれた（ゲーム内の感覚で打つ人がいる）
2. プレイヤーがワールドで `/stop` した場合はコンソールを通らないので、ログから
   畳まれ方を見る

ログ側は「誰が止めたか」ではなく**「整然と畳まれたか」**を見る。シャットダウン処理
自身が出す `Stopping server` が印で、クラッシュの標識（`Encountered an unexpected
exception` 等）が先に出ていたら付けない。`/stop` のコマンドフィードバック
`Stopping the server` を使う手もあるが、プレイヤー実行時は gamerule `logAdminCommands` に
依存し、切られた環境では出ない。シャットダウンの告知はゲームルールの影響を受けない。

**終了コードは判定に使えない。** クラッシュでもクラッシュレポートを書いた後に正常終了の
経路を通り 0 で終わる。逆に印が効くのは終了コードが 0 のときだけなので、外部からの
SIGTERM（143）はクラッシュ扱いのまま残り、自動再起動の対象になる。印はログのキューが
溢れても落ちないよう、キューに渡す前の読み取り側で拾う。

クラッシュループ対策として、起動から 60 秒以内の終了が 3 回続いたら打ち切って三択へ
落とす。60 秒以上もった世代が 1 つでもあれば履歴は捨てる（長くもったなら立ち直っている）。
起動スクリプトが java を起動せずに終わった場合は設定の誤りなので 1 回で打ち切る。

## 表示言語

**日本語版と英語版は別バイナリにする。単一バイナリに 2 言語を同居させない。**

ユーザーに見せる文字列は `internal/msg` に集約し、`msg_ja.go`（`//go:build !en`、既定）と
`msg_en.go`（`//go:build en`）が**同じ識別子を宣言する**。片方で書き忘れるとそのタグで
コンパイルが落ちる。**これが訳抜けの唯一の検出手段**なので、map や実行時 fallback には
しない。

- 値を埋め込むものは const の書式文字列ではなく関数にする。const だと ja と en で verb が
  ずれても気付けない
- **実行時のロケール判定・言語フラグ・カタログ探索は持たない。** `-ldflags -X` での
  切り替えもしない（両言語の文字列が同じバイナリに入ってしまう）
- `msg` に入れるのは設定モーダル・セットアップ・設定の検証エラー・操作結果など
  **普通のユーザーが読む文字列だけ**。hsperfdata や `/proc` のパースエラーのような
  開発者向け診断は両言語とも英語リテラルのまま各パッケージに置く
- 設定ファイル名もアーカイブ内の実行ファイル名も両言語とも `hso.toml` / `hso`。
  インストール手順を言語で分岐させない

## 配布

- **実行時依存ゼロ。** Go のインストールも不要。バイナリ 1 個を置いて実行するだけ
- `CGO_ENABLED=0` で完全静的リンク。glibc に依存しないので Alpine（musl）でも動く。
  **リリースビルドでは必須**。サイズは 8〜15MB 程度
- `linux/amd64` と `linux/arm64` の両方を出す（Oracle Cloud Ampere / Raspberry Pi での
  ホストが多いため）
- GitHub Releases。`v*` タグの push で arch × lang の 4 本を tar.gz にする
  （goreleaser は使わない）
- v2 の Fabric mod jar は `//go:embed` で埋め込み `hso install-mod` で書き出す。
  **ユーザーから見える成果物はバイナリ 1 個**に保つ

## 技術調査メモ

### バニラ GUI の数字の正体

プロセス内部で `Runtime.getRuntime()` を呼んでいるだけ。

- `used = totalMemory() - freeMemory()`
- `total = totalMemory()` = **committed heap**（`-Xmx` ではない。起動直後は小さい）
- `Avg tick` は `MinecraftServer` 内部の tickTimes 配列の平均

**GUI 自体が性能ペナルティ源**（ログペインが全行をメモリ保持する等、
[MC-135443](https://bugs-legacy.mojang.com/browse/MC-135443)）なので活用する価値はない。
ただし **`tickTimes` の更新は GUI の有無と無関係にティックループ内で常に走っている**ため、
データはヘッドレスでもプロセス内に存在する。これが v2 で TPS を取れる根拠。

### メモリ取得方法の比較

| 方式 | 判定 |
|---|---|
| **hsperfdata 直読み** | ★採用。HotSpot が**フラグ不要のデフォルトで**書いている mmap 領域で、`jstat` はこれを読んでいるだけ。バニラ GUI と同じ数字を完全再現でき情報量は上。パーサ自作が必要（〜250 行）。同一 UID が必要だがラッパーなら自明に満たす |
| **`-Xlog:gc` パース** | ★採用。`2048M->512M(4096M) 12.345ms` から GC 前後・停止時間。**GC 直後の谷 = 真のメモリ逼迫指標**。イベント駆動なので連続値にならず hsperfdata の補完。`file=` 必須（stdout に混ぜるとコンソールが汚れる） |
| **`/proc` RSS + cgroup** | ★採用。依存ゼロで必ず取れる最下層。**OOM Kill を予測できるのはこれだけ** |
| Attach API 自前実装 | 不採用。SIGQUIT を使うのが行儀悪く、テキスト出力でバージョン差に弱い |
| JMX 注入 | 不採用。クライアントが RMI で Go から喋るのが非常に面倒 |

### 既存ツール

| ツール | 評価 |
|---|---|
| [mark2](https://github.com/mark2devel/mark2) | 最も近い。CPU / メモリ / プレイヤー一覧をパネル表示するが Python/Twisted 製で開発停滞（open PR 0、Collaborators Needed） |
| [mcServerWrapper](https://github.com/ezterry/mcServerWrapper) | curses 製・軽量だが機能が少ない |
| [mcrcon](https://github.com/tiiffi/mcrcon) / [minecraft-tui](https://github.com/rdlu/minecraft-tui) | コマンド送信のみ。監視機能なし |
| Pterodactyl / Crafty Controller / MCSManager | 重量級 Web パネル。位置づけが違う |
| [minecraft-prometheus-exporter](https://github.com/sladkoff/minecraft-prometheus-exporter) | Bukkit/Paper プラグイン必須で**バニラ不可**。Prometheus + Grafana 前提 |

→ 「バニラで、プラグインなしで、ラッパーとして、ヒープと RSS を両方出す」ものは存在しない。

### TPS と Fabric mod（v2）

TPS / avg tick は**外部から取得する手段が事実上ない**。hsperfdata にも GC ログにも tick
情報はなく、バニラに `/tps` もない（Paper/Spigot 限定）。正確な値には
`MinecraftServer.tickTimes` へのアクセス = プロセス内へのコード注入が必須。

**`-javaagent` ではなく Fabric mod を採用する。**

| | `-javaagent` | Fabric mod |
|---|---|---|
| ロード主体 | JVM 本体 | Fabric Loader |
| 配置 | 任意パス、フラグで明示 | `mods/` に置くだけ |
| 起動コマンド変更 | **必要** | **不要** |
| 難読化対処 | **自前でマッピング取得・追従が必要**（バニラ jar は ProGuard 難読化済みで、`tickTimes` → `tickTimesNanos` のように名前も型もバージョンで変わる） | Loom が自動処理、公式 API あり |
| 対象 | バニラ含む何でも | Fabric サーバーのみ |

agent 方式は「マイクラのバージョンアップ追従を永続的に背負う」選択であり、TPS のためだけに
払うコストとして見合わない。Fabric mod なら同じことが 50 行程度で書ける。

mod → hso の受け渡しは **stdout に prefix 付きで出力**（`[HSO] tick_ms=4.32`）が最も安い。
hso は既に stdout を読んでいるので IPC が不要。汚くなったら Unix ドメインソケットへ移す。

mod が開ける扉は TPS だけではなく、MSPT 分布（p95 / 最大）・次元ごとの tick 時間・
ロード済みチャンク数・エンティティ数・プレイヤーごとの Ping まで届く
（= プラグインなしの spark 相当）。

## 状況

**v1 完了**: 起動スクリプトのラップと java PID 特定、hsperfdata パーサ、`/proc` + cgroup、
`JAVA_TOOL_OPTIONS` 注入と GC ログ tail、ログ分類、TUI（Stats / Meters / Players /
Graph / Chat / Log / Console）、コマンド送信と restart / stop、パネル選択とスクロール、
プレイヤーコマンドのモーダル、公開 IPv4 表示、amd64 / arm64 リリース。

**v2**: Fabric mod による TPS / MSPT 取得、`hso install-mod`。

**v3 以降**: 表示要素・レイアウトのカスタマイズ、バニラ向け `-javaagent` 方式
（マッピング取得基盤ごと）。Windows 対応は検討のみ — hsperfdata は
`%TEMP%\hsperfdata_<user>\<pid>` にあるので流用できるが、RSS 取得に Win32 API
（`GetProcessMemoryInfo`）が要り `CGO_ENABLED=0` の静的ビルド方針と衝突する。優先度は低い。
